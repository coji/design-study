# 試作 2: 指して、一言いって、選ぶ

気になるところを指して一言いうと、本物の AI がそこを変えた案を作る。元のままを 1 つ混ぜて 4 つ並べ、選んだあとに、何を変えた案だったかと、理論帳との関係を出す。

## 動かす

```sh
cd prototypes/02-say-and-pick
npm start          # http://127.0.0.1:4302 を開く
npm run mock       # AI を呼ばずに、前回の 1 回分（out/last-round.json）を、届いた間合いのまま再生する
```

`index.html` と `app/` は、ブラウザを再読み込みすれば反映される。`server.mjs`、`ai.mjs`、`shot.mjs` は、`npm start` が変更を見て自動で起動し直す。すでに動いているときに起動すると「もう動いています」と出る。

`npm run mock` は、どこを指しても前回の案をそのまま当てる。待っている間の見え方を、ChatGPT の枠を使わずに何度でも確かめるためのもの。`MOCK_SPEED=6 npm run mock` で 6 倍速になる。

準備が 3 つ要る。どれも下調べ（`lab/README.md`）で済ませたものを借りている。

- `lab/` で `npm install` を済ませていること（撮影と取り込みに、Playwright と手元の Chrome を使う）
- `vendor/sign-in-with-chatgpt-devkit` をビルドしてあること（画像を通すための 1 か所の変更も入れる）
  - DevKit には、もう 1 か所変更を入れている。`packages/local/dist/responses.js` の送信する本文に `...(options.extra ?? {})` を足し、考える深さ（`reasoning.effort`）を渡せるようにした
- ChatGPT にサインインしてあること。まだなら、最初に AI を呼ぶときにブラウザが開く

## 流れ

1. 左上で画面を選ぶ。「＋ 別の画面を取り込む…」に URL を入れると、その画面を写しとして取り込む（数秒）
2. 左の画面で、気になるところをクリックする。文字、ボタン、余白や入れ物を指せる。いまの値が右に出る
   - 範囲（入れ物や余白）を指すと、中の文字サイズの種類、左端の本数、箱の数などを数えて出す。案は、原因の仮説ごとに 1 つで、範囲の中の複数の要素を同時に変える
3. 右下に一言書く。4 つの枠がすぐ並び、できた案から覆いが外れる。途中で「やめる」と、一言を直して送り直せる
   - AI は、まず読みと 3 つの方向を短く決め（10 秒ほど）、方向が決まるたびに、その案を別の呼び出しで作り始める。元の画面の判定も別の呼び出しで作る。合わせて 5 つの呼び出しになる
   - 4 枚そろうまで 28〜36 秒ほど。読みは 7 秒ほどで流れ始める
   - 方向の名前は、選ぶ前には出さない。目で選んでから言葉を知る、という順を守るため
   - 元のままを出す順番は、毎回ばらつかせる（最初の案より前、または 1〜3 番目の案の少しあと）。いつも同じ順で出ると、どれが元かを届く順から推測できてしまう
4. 案をクリックすると大きく見られる。← → で、同じ位置のまま A〜D を切り替える。Esc で並べた画面に戻る。良いと思ったら「A を選ぶ」（Enter）。どれも違うときは、もう一言書いて「作り直す」
5. 選ぶと、理論帳と合うか食い違うか、AI の説明、アプリが画面から測った変化が出る。左上で、元と案を同じ位置で切り替えられる（O キーでも）
6. 選んだ理由を一言残す。理論帳の項目に事例が積まれ、製品のコーディングエージェントに渡す指示文が出る

## ファイル

- `index.html`: 骨組みと見た目（CSS）。枠は無彩色で、文字は 12/14/16px、余白は 4 の倍数、角丸は 4px と 12px、操作する部品の高さは 32px
- `app/main.js`: 画面の動き。1 回の流れを、指す → 一言 → 待つ → 選ぶ → 残す → 記録した、の段階で持つ。段階ごとの入力欄とボタンは `composer()` の 1 か所で決める
- `app/stage.js`: 左の画面。写しを入れた枠を 4 つ開いたままにして、並べる、大きく見る、元と案を切り替える、幅を変える、のどれでも読み込み直さない
- `app/measure.js`: 写しの中の要素を測る（値、行数、フォントにない太さの代用、範囲の中の数）
- `app/dom.js`: 画面の部品を作る小道具
- `server.mjs`: 画面と写しを配り、取り込み、AI への取り次ぎ、記録の保存をする
- `ai.mjs`: Sign in with ChatGPT で Responses API を呼ぶ。指示文と、理論帳（`docs/theory-v0.md`）の渡し方はここにある
- `shot.mjs`: 指したあたりを撮る。記録に残す画像も撮る。本番のアプリでは Electron の内蔵 Chromium に置き換える
- `copy/<名前>/`: 取り込んだ写し（`snapshot.html`、`assets/`、`meta.json`）。リポジトリに入れるのは `techtalk-jp` だけ
- `out/<日時>/`: 記録。1 回 1 フォルダで、`record.md`（人が読む）、`record.json`（機械が読む）、元と各案の画像（`pc-A.jpg`〜`sp-D.jpg`。2 つの幅で、同じ位置で撮る）。右の列の「記録」から「見直す」で、そのときの画面とやりとりを見られる。リポジトリには入れない

## できないこと

- ログインが要る画面は取り込めない（取り込みは、ログインしていない Chrome で開く）
- 取り込んだ写しが元と一致するかの確認（画像の比較）は、していない。`lab/` の手順で手で確かめる
- 選んだ案は、写しには書き戻さない。次の回も、取り込んだときの画面から始まる
- 記録は、このフォルダの `out/` に置いている。設計メモの「別の非公開の場所」には、まだ分けていない
